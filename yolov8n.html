Who Controls Each Version

No single owner — YOLO has been forked and continued by many groups

Joseph Redmon v1 · v2 · v3

Original creator of YOLO and the Darknet framework. Invented the single-pass detection concept. Stopped development in 2018 citing ethical concerns over military use of computer vision.

Alexey Bochkovskiy v4

Community continuation after Redmon quit. Forked Darknet (AlexeyAB/darknet) and pushed accuracy & speed further with CSPDarknet53 and advanced training tricks.

WongKinYiu v7 · v9

Independent research team. Produced YOLOv7 (E-ELAN) and YOLOv9 (PGI+GELAN) — both set new state-of-the-art benchmarks at release.

Ultralytics v5 · v8 · v11

Most commercially active maintainer today (Glen Jocher). Rewrote YOLO in PyTorch (v5), introduced anchor-free detection (v8), and improved efficiency (v11). Provides the widely-used ultralytics Python package.

Meituan v6

Chinese tech company. Built YOLOv6 focused on industrial applications and edge deployment with efficient reparameterisation techniques.

Tsinghua University v10

Academic research team. Introduced NMS-free end-to-end detection in YOLOv10 using dual-assignment training strategy — eliminating post-processing.

Key takeaway: There is no single owner of the YOLO name. It is open-source and has been independently forked and improved by universities, companies, and individual researchers worldwide.

An open-source neural network framework written by Joseph Redmon in C and CUDA.

C + CUDAFast, low-level, minimal dependencies

YOLO Specialty — Single Pass

Why one forward pass through a CNN makes YOLO revolutionary

R-CNN — Multiple Passes (slow)

Original Image
Region Proposal → cut ~2000 pieces
crop 1 → CNN layers → result
crop 2 → CNN layers → result
crop 3 → CNN layers → result
... 2000 times total
CNN runs 2000× on same image = Very Slow

YOLO — Single Pass (fast)

Full Image (640×640)
CNN Layer 1 → Layer 2 → ··· → Layer N
one continuous flow, no cutting
S×S Grid — all cells predicted at once
every cell outputs box + class simultaneously
All objects found in one forward pass
CNN runs 1× on full image = Real-time

Grid system — how all objects are found at once

Image divided into S×S grid
●
● = object center falls here → this cell predicts it
Each cell predictsMeaning
x, yObject center position
w, hBox width & height
confidenceIs there an object here?
class scoresWhat type of object?
All S×S cells make their predictions simultaneously in one forward pass — that is why YOLO is fast.

Backbone — CSPDarknet + C2f

Feature extraction engine: from pixels to rich semantic feature maps

CSP — Cross Stage Partial Network

CSP splits the feature map into two paths so heavy computation only runs on one — then merges both.

Input feature map
Branch A
Heavy Conv
Bottleneck 1
Bottleneck 2
Branch B
Direct skip
(no conv)
Concat → Conv → Output
💡
Half the computation, same accuracy. Branch B acts as a gradient highway for backpropagation.

C2f — Cross Stage Partial with 2 Flows

YOLOv8's improved version of C3 (YOLOv5). More gradient paths = richer learning.

Input ↓ split into 2 Branch 1 → direct (skip) Branch 2 → Bottleneck 1 → Bottleneck 2 → ... All intermediate outputs ↓ concat together Conv → Output
More gradient flow paths → better feature learning → higher accuracy than C3 at same speed.

SiLU Activation (used throughout YOLOv8)

SiLU(x) = x × sigmoid(x) = x / (1 + e⁻ˣ)

Smoother than ReLU — negative values are not completely killed, just dampened. Leads to better gradient flow and higher accuracy.

Neck — PAN-FPN

Fuses multi-scale features so all object sizes are detected accurately

Why a Neck is needed

The backbone's different layers see the image at different resolutions:

Feature mapGridCell sizeGood for
P380×808pxSmall objects
P440×4016pxMedium objects
P520×2032pxLarge objects

The neck enriches each scale with information from the others so even small scales know about context and large scales keep fine detail.

FPN + PAN — two pathways

↓ FPN (top-down)
Deep semantic features flow from P5 → P4 → P3 via upsampling + concatenation
↑ PAN (bottom-up)
Spatial detail flows back from P3 → P4 → P5 via downsampling + concatenation
= Result: enriched features at all 3 scales
Each scale now has both semantic (WHAT) and spatial (WHERE) information

Head — Decoupled & Anchor-Free

Two major innovations that make YOLOv8 more accurate than previous versions

Innovation 1 — Decoupled Head

Old: Coupled (v5)
Feature map

Tasks interfere with each other
New: Decoupled (v8)

branch
(What?)
Regression
branch
(Where?)
Each task optimises independently

Innovation 2 — Anchor-Free

Anchor-based (v5)
Pre-defined anchor box sizes for each cell. Model predicts offsets from anchors. Anchors must be tuned per dataset using k-means.
Anchor-free (v8)
Directly predicts center x, y, width, height from scratch. No preset shapes needed. Works better across diverse datasets.
Task-Aligned Assigner (TAL) assigns best grid cells to each object automatically

SPPF Module

Spatial Pyramid Pooling Fast — captures multi-scale context at end of backbone

What SPPF does

Applied at the deepest backbone layer (20×20×512). Captures context from multiple receptive field sizes without changing spatial dimensions.

Input: 20×20×512 ↓ MaxPool(5×5) → 20×20×512 ↓ MaxPool(5×5) → 20×20×512 ↓ MaxPool(5×5) → 20×20×512 ↓ Concat all 4 → 20×20×2048 ↓ Conv(1×1) → 20×20×512

SPPF vs SPP

PropertySPP (old)SPPF (new)
Pool type3 parallel pools3 series pools
Pool sizes5×5, 9×9, 13×135×5 × 3 times
SpeedSlower2× faster
ResultSameSame accuracy
💡
Three serial MaxPools of size 5×5 effectively cover receptive fields of 5, 9, and 13 — identical to SPP but 2× faster.

Anchor-Free vs Anchor-Based

A concrete comparison of how boxes are predicted

Anchor-Based (YOLOv5)

Step 1: Pre-compute 3 anchors per scale (k-means on dataset bounding boxes) Anchor 1: [10×13] ← small Anchor 2: [33×23] ← medium Anchor 3: [116×90] ← large Step 2: Model predicts offsets tx, ty ← offset from anchor center tw, th ← scale factor of anchor size Step 3: Final box bx = sigmoid(tx) + cx by = sigmoid(ty) + cy bw = anchor_w × e^tw bh = anchor_h × e^th
Problem: anchors must be recalculated for every new dataset

Anchor-Free (YOLOv8)

No pre-computation needed! Model directly predicts: cx, cy ← center of box w, h ← width and height Uses Distribution Focal Loss (DFL): Instead of single value, predicts probability distribution of possible edge positions → more accurate box edges Task-Aligned Assigner (TAL): Dynamically assigns which cells are responsible for each object
Works out-of-the-box on any dataset — no anchor tuning

Loss Functions

Three components tell the model how wrong it was during training

Classification Loss

Binary Cross-Entropy

Is this class present? YES or NO per class independently. Allows multi-label detection (one box can be multiple classes).

BCE = −[y·log(p) + (1−y)·log(1−p)]

Box Regression Loss

CIoU Loss

Measures how well the predicted box overlaps the real box. CIoU includes overlap area + center distance + aspect ratio.

IoU = Overlap Area / Union Area

Distribution Focal Loss

DFL

For anchor-free box regression. Predicts a distribution of likely edge positions instead of a single value — more robust predictions.

DFL = −((y₁+1−y)log(pᵢ)+(y−y₀)log(pᵢ₊₁))

Total Loss

Total Loss = λ₁ × BCE_cls + λ₂ × CIoU_box + λ₃ × DFL
IoU = 1.0
Perfect overlap — predicted box exactly matches ground truth
IoU = 0.5
50% overlap — acceptable but needs improvement
IoU = 0.0
No overlap — predicted box completely wrong

Full Inference Pipeline

Step-by-step: what happens when you feed an image to YOLOv8n

Step 1 — Pre-process
Resize to 640×640 · Normalize (÷255) · Add batch dim → shape (1, 3, 640, 640)
Step 2 — Backbone (CSPDarknet + C2f + SPPF)
Extract feature maps at P3 (80×80), P4 (40×40), P5 (20×20)
Step 3 — Neck (PAN-FPN)
Fuse features top-down and bottom-up across all 3 scales
Step 4 — Head (Decoupled, Anchor-free)
Classification branch + Regression branch independently at each scale
Step 5 — Post-process
Confidence threshold (e.g. 0.25) → filter low-confidence boxes → NMS → remove duplicates
Output
[x1, y1, x2, y2, confidence, class_id] per detected object

NMS — Non-Maximum Suppression

Before NMS — multiple overlapping boxes for same object:
Box A: 95%
Box B: 82%
Box C: 71%
After NMS — only highest confidence kept:
Box A: 95% ✓ kept
B, C removed
