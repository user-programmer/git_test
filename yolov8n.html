The Darknet Framework

The engine that powered early YOLO

What is Darknet

  • ►Written in C and CUDA by Joseph Redmon
  • ►Fast, lightweight, minimal dependencies
  • ►Supports CPU and GPU
  • ►YOLO was built ON TOP of Darknet
  • ►Backbone names (Darknet-19, CSPDarknet53) come from it
Config format: .cfg + .weights files defined the entire model architecture and parameters

Evolution After Redmon

Darknet (Redmon)
Original C/CUDA framework
AlexeyAB fork
Added YOLOv4 support
PyTorch era
YOLOv5 onwards moved to Python/PyTorch
Ultralytics
Modern Python API, pip install ultralytics
Why the shift? PyTorch is easier to use, debug, and extend than C. The speed advantage of C became less important as GPU libraries improved.

The Single-Pass Revolution

Why YOLO changed object detection forever

R-CNN Approach — SLOW

1.Selective Search proposes ~2000 region candidates
2.Each region resized to fixed size
3.EACH region goes through CNN separately
4.Classify each region
Result: ~2000 CNN forward passes per image
Speed: < 1 FPS (cannot do real-time)

YOLO Approach — FAST

1.Resize full image to fixed size (e.g. 640×640)
2.ONE forward pass through CNN
3.CNN outputs predictions for ALL locations simultaneously
Result: 1 CNN forward pass per image
Speed: 30–300+ FPS (real-time capable)

What is FPS?

Frames Per Second — how many images the model can process in 1 second.

FPS = 1000ms / Inference Time

Higher = faster. Real-time video requires at least 24–30 FPS.

What does ~ mean?

The tilde (~) means "approximately". These benchmarks vary by hardware, batch size, and implementation. They give relative comparisons, not exact values.

What does < mean?

The less-than sign (<) means "less than". "<1 FPS" means under 1 frame per second — essentially not real-time capable.

What is mAP?

Mean Average Precision — the standard accuracy metric for object detection. Considers both precision (are detections correct?) and recall (did we find all objects?). Higher = better. Calculated across all object classes on COCO dataset.

Backbone — CSPDarknet + C2f

Feature extraction: from pixels to rich semantic feature maps

CSP — Cross Stage Partial

Splits feature map into 2 paths — heavy conv on one, direct skip on the other — then merges both. Half the computation, same accuracy.

Branch A — Heavy Conv
Bottleneck 1 → Bottleneck 2
Branch B — Direct skip (no conv)
Concat → Conv → Output
💡
Branch B is a gradient highway — backpropagation flows through it cleanly, improving training stability.

C2f — Cross Stage Partial with 2 Flows

YOLOv8's improved C3 (YOLOv5). More gradient paths = richer learning.

Input ↓ split Flow 1 → direct Flow 2 → Bottleneck 1 → Bottleneck 2 ... All outputs ↓ concat Conv → Output
More gradient flow paths → better accuracy than C3 at the same speed.

SiLU Activation (used throughout)

SiLU(x) = x × sigmoid(x) = x / (1 + e⁻ˣ)

Smoother than ReLU — negatives dampened, not killed. Better gradient flow → higher accuracy.

The neck enriches each scale with information from the others so all sizes benefit from both context and detail.

FPN + PAN — two pathways

↓ FPN (top-down)
Deep semantic features flow P5 → P4 → P3 via upsampling + concat
↑ PAN (bottom-up)
Spatial detail flows back P3 → P4 → P5 via downsampling + concat

Innovation 2 — Anchor-Free

v5 — Anchor-based
Pre-defined anchor sizes per cell. Model predicts offsets. Anchors must be tuned per dataset.
v8 — Anchor-free
Directly predicts cx, cy, w, h. No preset shapes. Works across diverse datasets out-of-the-box.
Task-Aligned Assigner (TAL) automatically assigns best cells to each object

SPPF Module

Spatial Pyramid Pooling Fast — multi-scale context at end of backbone

How SPPF works

Applied at P5 (20×20×512). Captures context at multiple receptive field sizes without changing spatial dimensions.

Input: 20×20×512 ↓ MaxPool(5×5) → 20×20×512 ↓ MaxPool(5×5) → 20×20×512 ↓ MaxPool(5×5) → 20×20×512 ↓ Concat all 4 → 20×20×2048 ↓ Conv(1×1) → 20×20×512

SPPF vs SPP

PropertySPP (old)SPPF (new)
Pooling3 parallel pools3 series pools
Sizes5×5, 9×9, 13×135×5 × 3
SpeedSlower2× faster
AccuracySameSame
💡
Three serial 5×5 MaxPools cover effective receptive fields of 5, 9, and 13 — identical to SPP but 2× faster.

Anchor-Free vs Anchor-Based

Concrete code-level comparison of how boxes are predicted

Anchor-Based (YOLOv5)

Step 1: Pre-compute anchors (k-means) [10×13] [33×23] [116×90] Step 2: Predict offsets tx, ty ← offset from anchor center tw, th ← scale factor of anchor Step 3: Decode box bx = sigmoid(tx) + cx bw = anchor_w × e^tw
Anchors must be recalculated for every new dataset using k-means clustering

Anchor-Free (YOLOv8)

No pre-computation needed! Directly predicts: cx, cy ← center of object w, h ← box dimensions Uses Distribution Focal Loss (DFL): Predicts probability distribution of edge positions → more accurate TAL assigns responsible cells dynamically per object
Works on any dataset without anchor tuning

Loss Functions

Three components that tell the model how wrong it was during training

Classification Loss

Binary Cross-Entropy

Is this class present — YES or NO per class independently. Allows multi-label detection.

BCE = −[y·log(p) + (1−y)·log(1−p)]

Box Regression Loss

CIoU Loss

Measures box overlap + center distance + aspect ratio together. Better than plain IoU.

IoU = Overlap / Union Area

Distribution Focal Loss

DFL

Predicts distribution of likely box edge positions instead of a single value — more robust.

Total = λ₁·BCE + λ₂·CIoU + λ₃·DFL

IoU — Intersection over Union

IoU = 1.0
Perfect — predicted box exactly matches ground truth
IoU = 0.5
50% overlap — acceptable but needs improvement
IoU = 0.0
No overlap — predicted box completely wrong

Full Inference Pipeline

Step-by-step: what happens when you feed an image to YOLOv8n

Step 1 — Pre-process
Resize 640×640 · Normalize ÷255 · Add batch dim → (1,3,640,640)
Step 2 — Backbone
CSPDarknet + C2f + SPPF → feature maps at P3/P4/P5
Step 3 — Neck (PAN-FPN)
Fuse features top-down and bottom-up across 3 scales
Step 4 — Head (Decoupled, Anchor-free)
Cls branch + Reg branch independently at each of the 3 scales
Step 5 — Post-process
Confidence threshold (0.25) → filter boxes → NMS → remove duplicates → scale back
✅ Output
[x1, y1, x2, y2, confidence, class_id] per detected object

NMS — Non-Maximum Suppression

Before NMS — multiple overlapping boxes:
Box A: 95%
Box B: 82%
Box C: 71%
After NMS — highest confidence kept:
Box A: 95% ✓
B, C removed
